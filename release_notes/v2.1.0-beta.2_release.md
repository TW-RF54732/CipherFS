# CipherFS v2.1.0-beta.2 - Read-Only Filesystem Refactor

This prerelease continues the v2.1 performance test series while separating
the read-only filesystem core from the Linux FUSE adapter. It remains an
experimental build and does not replace v2.0.0 as the recommended stable
release.

## Changes

- Splits the former FUSE-specific mount implementation into a platform-neutral
  read-only filesystem core and a Linux FUSE adapter.
- Preserves the existing Linux read-only mount behavior while preparing a
  cleaner boundary for a future Windows WinFSP adapter.
- Keeps corruption handling in the shared core: authenticated read failures
  return an error and do not expose partial plaintext.
- Fixes `pack` with a default or filename-only relative output path, such as
  `target_folder.cfs`, incorrectly reporting `No such file or directory`
  after the container had already been created and verified.
- Adds an explicit `[Info] Verifying completed container...` message for the
  full self-verification pass that runs after the encryption progress bar
  reaches 100%.
- Retains the experimental parallel chunk processing and `--threads` controls
  introduced in v2.1.0-beta.1.

## Platform Scope

This release publishes the existing static Linux x86-64 binary and supports
Linux FUSE mounting. The platform-neutral refactor is preparation for WinFSP;
this release does not yet provide a Windows mount binary or claim WinFSP
support.

## Performance Status

Parallel performance remains experimental. Field tests on WSL2 showed
environmental stalls and inconsistent timing across both stable and beta
builds, so those runs are retained as observations rather than treated as a
release-to-release performance conclusion.

Use the downloaded release binary, a new output directory for every run, and
record the filesystem path, thread count, file count, byte count, and actual
wall-clock time. Do not compare progress-bar ETA values or an unoptimized
`cargo run` build with a release binary.

## Validation and Safety

- The platform-neutral read-only filesystem core has unit coverage for lookup,
  directory enumeration, range reads, and corruption failures.
- Packing performs a complete authenticated self-verification before the
  temporary container is installed at its final path.
- Extraction continues to delay final-name commits until encrypted chunks have
  authenticated.
- The CipherFS v2 on-disk format remains unchanged and compatible with v2.0.0
  and v2.1.0-beta.1.

CipherFS remains an unaudited experimental hobby project for casual/offline
privacy of non-critical files. Keep independent backups and do not treat this
prerelease as a security, reliability, or performance guarantee.
