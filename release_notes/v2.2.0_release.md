# CipherFS v2.2.0 - Linux and Windows stable release

CipherFS v2.2.0 is the first release whose Linux FUSE and Windows WinFsp builds
share the same validated v2 read-only core and are both required to pass runtime
mount tests before release. “Stable” describes the supported release workflow;
CipherFS remains an experimental privacy tool for non-critical files and has
not received a professional security audit.

## Changes

- Supports v2 containers on Linux x86-64/FUSE 3 and Windows x86-64/WinFsp 2.1.
- Removes the legacy v1 reader from the stable binary. Trusted v1 data must be
  extracted with an archived beta and repacked as v2.
- Makes extraction whole-tree transactional: the destination must not exist and
  appears only after every file has authenticated and the staging tree commits.
- Rejects symlink, junction and reparse-point ancestors for extraction and
  Windows folder mounts.
- Uses deterministic Windows ordinal/NTFS-aware name collision handling,
  including DOS reserved and overlong names.
- Adds `--version`, complete embedded licensing notices, dependency policy,
  CodeQL, signed per-platform manifests and exact-source release assets.
- Adds deterministic pre-commit write/source-change fault tests and a real
  Windows running-executable replacement test for the updater.

## Windows requirements and limitations

Install the official WinFsp 2.1 runtime separately. The portable zip/raw exe
does not bundle a driver or installer. The executable is not Authenticode-signed
and may trigger SmartScreen; verify its Minisign manifest, SHA-256 and GitHub
Artifact Attestation. The combined Windows executable is conveyed under GPLv3
because it incorporates `winfsp-rs`; `cipherfs licenses` prints the full notice.

CipherFS does not preserve ACLs, ownership, timestamps, xattrs, alternate data
streams, hard-link identity, sparse allocation or filesystem-specific metadata.
Keep independent backups and do not use CipherFS as the sole protection for
sensitive, valuable or irreplaceable data.
