# CipherFS v3.1.0-beta - Windows Shell and workspace refactor

CipherFS v3.1.0-beta is an experimental prerelease. It keeps the v2 container
format and established `cipherfs` CLI contract compatible with v3.0.0 while
introducing a separated Cargo workspace and an optional Windows Explorer
frontend. It has not received a professional security audit; keep independent
backups and do not use it as the sole protection for valuable or irreplaceable
data.

## Highlights

- Adds `cipherfs-shell.exe`, a portable native Windows frontend for opening a
  `.cfs` container or packing a directory passed by Explorer.
- Adds optional per-user Explorer integration: an Open With handler for `.cfs`
  and **Pack with CipherFS** for folders. Windows 11 exposes the static folder
  verb under **Show more options**. It does not alter `UserChoice` defaults.
- Moves the implementation into separate `core`, FUSE, WinFsp, updater, CLI,
  and Windows Shell packages. The core has no UI, mount, terminal, Registry or
  network dependency.
- Adds typed operation errors, monotonic progress events, cooperative
  cancellation, transactional temporary-output cleanup, and RAII mount
  sessions.
- Runs Windows Shell operations in an isolated child process. Passwords travel
  only through versioned MessagePack pipes, never command-line arguments,
  environment variables, files, history, or logs. A second confirmed cancel
  terminates only that worker, not the shell process.
- Adds a signed eight-field Windows integration manifest for the two-binary
  managed-update path while retaining the legacy five-field CLI manifest for
  portable `cipherfs.exe` updates.

## Compatibility and requirements

- New and existing v2 containers remain compatible. Cryptographic parameters,
  v2 on-disk layout and the existing CLI commands remain unchanged.
- Linux releases contain the `cipherfs` CLI and require FUSE 3 for mounting.
- Windows releases contain `cipherfs.exe` and `cipherfs-shell.exe`. Pack,
  Extract, Verify and Change Password work portably; Mount requires the
  separately installed official WinFsp 2.1 runtime.
- The Windows combined executables are conveyed under GPLv3 because they use
  `winfsp-rs`; CipherFS-authored source remains available under MIT.

## Beta limitations

- The current Windows Shell uses traditional Win32/Credential UI. Its visual
  design and high-DPI presentation are scheduled for the later stable release;
  this beta prioritizes operation isolation and cancellation safety.
- The managed installer/updater is isolated from operations but does not yet
  implement cross-process locking, active-session exclusion, or a fully
  failure-injected two-binary replacement rollback. Do not update while an
  operation or mount is active.
- This prerelease does not replace GitHub's `releases/latest`. Download it
  explicitly for testing.
