# CipherFS v3.1.0 - Slint Windows Shell and layered testing

CipherFS v3.1.0 keeps the v2 container format and established `cipherfs` CLI
contract compatible with v3.0.0. It replaces CipherFS-owned Windows dialogs
with a single Slint interface while retaining Windows-owned file pickers,
Explorer integration, URL launching and standard window chrome. CipherFS
remains an experimental personal/offline privacy tool; it has not received a
professional security audit and must not be the only copy of valuable data.

## Highlights

- Adds a resizable, accessible dark Slint interface for passwords, operation
  selection, progress, cancellation, mount status, integration management,
  completion and errors.
- Keeps native Windows file selection, Explorer launching, `.cfs` Open With
  registration and **Pack with CipherFS** folder integration.
- Runs Pack, Extract, Verify, Change Password and mount work in isolated child
  workers with versioned MessagePack pipes, cooperative cancellation,
  protected commit/mutation phases and exact temporary-artifact cleanup.
- Adds functional Extract round-trip and failure E2E coverage, including wrong
  passwords, corrupt containers, existing destinations, worker crashes and
  staging cleanup.
- Adds real Slint callback tests, CLI-injected Pack/Verify/Extract/password
  workflows, explicit WinFsp runtime tests, renderer smoke tests and native
  picker gates.
- Adds resource-aware local test runners that select Windows Shell, CLI, Core,
  updater, WinFsp or FUSE packages from Git changes while CI retains complete
  Windows and Linux gates.

## Compatibility and requirements

- Existing v2 containers, cryptographic parameters, on-disk layout, CLI
  commands, worker protocol v1 and signed update manifests remain compatible.
- Linux releases contain the `cipherfs` CLI and require FUSE 3 for mounting.
- Windows releases contain `cipherfs.exe` and `cipherfs-shell.exe`. Portable
  Pack, Extract, Verify and Change Password do not require WinFsp; Mount
  requires the separately installed official WinFsp 2.1 runtime.
- Windows integration is installed per user and does not silently replace the
  Windows `UserChoice` default application.
- The Windows combined executables are conveyed under GPLv3 because they use
  `winfsp-rs`; CipherFS-authored source remains available under MIT.

## Known limitations

- Slint may create framework-managed copies of password strings. CipherFS
  clears visible fields promptly but cannot promise deterministic overwrite of
  every GUI-managed copy.
- The managed installer/updater does not yet provide cross-process locking,
  active-session exclusion or fully fault-injected two-binary rollback. Do not
  update while an operation or mount is active.
- Visual DPI, Narrator and Explorer policy behavior still require the manual
  Windows acceptance procedure documented in `TESTING.md` in addition to CI.
