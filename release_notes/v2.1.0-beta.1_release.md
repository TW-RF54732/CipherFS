# CipherFS v2.1.0-beta.1 - Parallel Chunk Processing Test Release

This is a prerelease for performance testing. It is not intended to replace
v2.0.0 as the recommended stable build.

## What to Test

- Adds concurrent encryption for independent 4 MiB v2 chunks during `pack`.
- Adds bounded, ordered concurrent chunk decryption during `extract`.
- Adds concurrent full-container chunk authentication during `verify` and the
  pack self-verification pass.
- Adds `--threads` to `pack`, `extract`, and `verify`. `--threads 0` uses the
  available CPU parallelism; a positive number limits the worker pool.
- Keeps the CipherFS v2 on-disk format unchanged and compatible with v2.0.0.

Use the downloaded release binary for timing. The default `cargo run` command
uses an unoptimized development build and is not comparable with a release
binary.

Suggested comparisons:

```bash
cipherfs extract vault.cfs output-1 --threads 1
cipherfs extract vault.cfs output-4 --threads 4
cipherfs extract vault.cfs output-auto --threads 0
```

Use a new empty output directory for each run.

## Known Performance Boundary

The included development benchmark used a release build on native WSL2 ext4
storage. It does not predict performance when a Linux binary accesses Windows
NTFS through `/mnt/c`. Cross-filesystem performance can vary substantially,
especially with many image files, concurrent positional I/O, real-time malware
scanning, and per-file synchronization.

For useful reports, include:

- whether the binary is this downloaded release asset;
- source, container, and output filesystem paths;
- `--threads` value;
- total bytes, file count, and approximate file-size distribution;
- separate pack, verify, and extract elapsed times.

Detailed engineering records are archived in
[`benchmarks/INDEX.md`](https://github.com/TW-RF54732/CipherFS/blob/v2.1.0-beta.1/benchmarks/INDEX.md),
including raw samples, the 26.7 GiB real-image observation, and the beta test
matrix. Intermediate and non-comparable results are retained and labeled rather
than discarded.

## Validation and Safety

- Extraction still writes to temporary files and delays final-name commits
  until every encrypted chunk has authenticated.
- Corrupted chunks remain authentication failures and do not produce committed
  output files.
- Parallelism is bounded by the worker count and extraction preserves chunk
  order.
- The existing v1 compatibility readers remain unchanged.

CipherFS remains an unaudited experimental hobby project for casual/offline
privacy of non-critical files. Keep independent backups and do not treat this
prerelease as a security or performance guarantee.
