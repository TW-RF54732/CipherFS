# CipherFS v2.0.0 - Experimental Personal Privacy Format

## Highlights

- Introduces the CipherFS v2 container with a 4 KiB authenticated header.
- Uses a random container ID, random per-file IDs, HKDF-SHA256 subkeys, and
  independent authenticated 4 MiB chunks for every file.
- Replaces the recursive Index with a validated flat Index and preserves empty
  directories.
- Adds full-container `verify`, bounded decrypted Chunk caching, safe temporary
  extraction, and strict `EIO` handling for authentication failures.
- Reworks the experimental Duress password with a separate Argon2id keyslot and
  adds crash-tolerant dual master-password keyslots.
- Keeps v1 mount/extract compatibility with legacy warnings and stricter local
  safety limits.

## Security and Stability

- Rejects `..`, absolute paths, multi-component names, and symbolic-link
  traversal during extraction.
- Validates IDs, parent relationships, depths, arithmetic, offsets, chunk
  counts, data contiguity, and exact container length before output.
- Writes pack and extract results through synchronized temporary files before
  atomic installation.
- Signed automatic updates verify a Minisign manifest, target, version, size,
  and SHA-256 before replacement.
- GitHub releases include Artifact Attestations for public build provenance.

## Local Performance Sample

On the recorded WSL2 development machine, three 1 GiB sequential FUSE reads
had a v1 median of 29.31 seconds and a v2 median of 2.37 seconds. Pack, extract,
random-read, and small-file samples are recorded in
[`benchmarks/2026-07-25-wsl2.md`](../benchmarks/2026-07-25-wsl2.md). These are
development measurements, not general performance guarantees.

## Compatibility

New `pack` operations create v2 containers only. Existing v1 containers can be
mounted or extracted but cannot use `passwd` or full `verify`. Extract trusted
v1 data and pack it again to move to v2.

CipherFS remains an unaudited hobby project. It does not prevent copying or
replay of an entire valid container, protect mounted plaintext, or guarantee
secure erasure.
