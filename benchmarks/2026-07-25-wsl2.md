# CipherFS v2 local performance sample

Date: 2026-07-25

This is a development sample, not a portable performance guarantee.

## Environment

- WSL2: Linux 6.18.33.2-microsoft-standard-WSL2, x86_64
- CPU: AMD Ryzen 9 5900HS, 16 logical CPUs exposed to WSL
- Rust: 1.95.0
- Build: native Linux `cargo build --locked --release`
- KDF used by benchmark containers: Argon2id, 8 MiB / t=1 / p=1
- v2 mount cache: 64 MiB
- Large input: one sparse 1 GiB file (the full logical data was still read,
  encrypted, authenticated, and returned through FUSE)

## 1 GiB sequential FUSE read

Both the legacy v1 container and the v2 container were mounted by the v2
binary. Each result is three reads on the same machine and mount; the median is
used for the release gate.

| Format | Runs (seconds) | Median |
| --- | --- | ---: |
| v1 | 30.25, 29.31, 28.74 | 29.31 s |
| v2 | 2.51, 2.18, 2.37 | 2.37 s |

The v2 median was approximately 91.9% lower than v1, so it satisfies the
requirement that sequential mount reads must not regress by more than 20%.
The large difference is expected because the v2 LRU avoids repeatedly
decrypting the same 4 MiB chunk for adjacent smaller FUSE reads.

## Additional v2 samples

| Operation | Result |
| --- | ---: |
| Pack one 1 GiB file | 4.23 s |
| Extract one 1 GiB file | 2.46 s |
| 100 distributed 4 KiB mounted reads | 0.85 s |
| Pack 5,000 files of 32 bytes | 5.50 s |
| Extract 5,000 files of 32 bytes | 10.67 s |

The timings include the reduced benchmark KDF and CLI/process overhead. They
should be compared only with future runs using the same procedure and machine.
